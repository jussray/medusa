# Customer workspace — activation boundary

The approved canon remains unchanged. Application script adds a receipt list and a separate consent-based save control. The server recalculates the evidence digest and exact quotation result; it never accepts caller-supplied verification status or owner identity. Only digest, match flags, server timestamp, receipt ID and customer ID are persisted. A digest can still be sensitive. Use non-sensitive evidence only.

The SQL migration is intended for a dedicated D1 database. Bind it as WORKSPACE_DB and enable MEDUSA_WORKSPACE_ENABLED only after a trusted customer identity service is installed, tenant lifecycle and retention rules are approved, request quotas and rate limits are established, and production isolation is tested. The private issuer must generate cryptographically random 32-byte lowercase hex opaque session tokens, store their SHA-256 hashes with customer ID, role=customer, expiration in milliseconds and revocation state, and issue a Secure, HttpOnly, SameSite=Lax, Path=/ __Host-medusa_customer cookie on this origin. No public session issuance, OAuth callbacks or founder provisioning exist in this change. Never share a session or token between founder and customer lanes. Do not manually mint production sessions to bypass OAuth. No deployment bindings are configured by this commit.

Local tests use an in-memory SQLite database with a D1-shaped adapter and fictional session tokens. No production D1 test, actual OAuth sign-in, browser workspace flow or paid AI call has been performed. The server defaults to disabled and /api/status continues to report customerAuth=false and aiRuntime=false until those capabilities are actually integrated.
